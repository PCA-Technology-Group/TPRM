========================================
1. CLIENTS AND VENDORS
========================================


CLIENT
------
ClientId (PK)
Name
CreatedDate
...


Purpose:

Represents a company purchasing and using the
TPRM service.


VENDOR
------
VendorId (PK)
Name
CreatedDate
...


Purpose:

Represents a real-world third-party company.

Under our working design, a Vendor exists once
globally.

Example:

Microsoft exists once even when multiple Clients
use Microsoft.


CLIENT_VENDOR
-------------
ClientVendorId (PK)

ClientId (FK -> Client)
VendorId (FK -> Vendor)

TierId (FK -> VendorTier)

CreatedDate
...


Constraint:

UNIQUE (ClientId, VendorId)


Purpose:

Represents the relationship between a Client and
Vendor.

It contains business information specific to that
relationship.


Example:

Acme Bank + Microsoft
Tier = 4

Capital One + Microsoft
Tier = 3


Tier belongs to CLIENT_VENDOR instead of VENDOR
because different Clients can classify the same
Vendor differently.


IMPORTANT:

This differs from the original requirements, which
model Vendor as belonging to one Client.

Our working design is:

Global Vendor
      +
ClientVendor relationship

========================================
6. CUSTOM QUESTION RULES
========================================


Clients cannot create or modify questions.

Clients communicate customization requests to
Netrio outside the platform.

A Netrio Admin creates/configures the question.


For the MVP, a custom question:

1. Is created only by Netrio Admin.

2. Belongs to one Client.

3. Can be reused in future Assessments for that
   Client.

4. Cannot be used by other Clients.

5. Does not become part of standard SIG.

6. Does not belong to a SIG Domain.

7. Does not participate in standard scoring.

========================================
10. ASSESSMENT QUESTION GENERATION
========================================


Initial standard question scope:

ClientVendor

    ↓

Tier

    ↓

TierDomain

    ↓

SIG Domain

    ↓

QuestionTemplate

    ↓

AssessmentQuestion snapshot


Process:

1. Create Assessment.

2. Read Tier from ClientVendor.

3. Store Tier as Assessment.TierIdSnapshot.

4. Retrieve configured SIG Domains for that Tier.

5. Retrieve SIG QuestionTemplates belonging to those
   Domains.

6. Create AssessmentQuestion snapshots.

7. Allow Netrio Admin to make permitted manual
   adjustments.

8. Freeze scope when Assessment is distributed.

========================================
12. MANUAL QUESTION ADJUSTMENTS
========================================


Before Distribution, Netrio Admin may:

- Add a Client-specific custom question.
- Exclude a standard question.
- Reverse an exclusion.


Clients do not directly perform these actions.


----------------------------------------
ADDING CUSTOM QUESTIONS
----------------------------------------

The custom question first exists as a reusable
Client-owned QuestionTemplate.

It is then copied into AssessmentQuestion.


Example:

QuestionTemplate:

Question:
"Does the Vendor permit customer-managed
encryption keys?"

Source = Custom

ClientId = Acme Bank


AssessmentQuestion:

QuestionTextSnapshot =
"Does the Vendor permit customer-managed
encryption keys?"

QuestionSourceSnapshot = Custom

AddedManually = true


========================================
13. QUESTION EXCLUSION
========================================


Questions are NOT physically deleted from the
Assessment.

They are marked as excluded.


Example:

Tier rules generate:

Q1
Q2
Q3
Q4
Q5


Netrio Admin removes Q3 from the questionnaire.


AssessmentQuestion Q3:

IsExcluded = true

ExcludedBy = user

ExcludedDate = timestamp

ExclusionReason =
"Not applicable to Vendor."


Vendor receives:

Q1
Q2
Q4
Q5


Purpose:

Preserves:

- What Tier rules originally selected
- What Netrio changed
- Who changed it
- When
- Why


Excluded questions:

- Are not shown to Vendor
- Cannot receive Responses
- Do not require Review
- Do not participate in scoring


========================================
14. ASSESSMENT SCOPE FREEZE
========================================


BEFORE DISTRIBUTION:

Netrio Admin may:

- Add custom questions
- Exclude questions
- Reverse exclusions


AFTER DISTRIBUTION:

Questions cannot be:

- Added
- Removed
- Excluded
- Restored
- Reworded
- Reweighted


The question scope becomes immutable when the
Assessment is distributed.


========================================
15. RESPONSES
========================================


RESPONSE
--------
ResponseId (PK)

AssessmentQuestionId
(FK -> AssessmentQuestion)

Answer

SubmittedBy
SubmittedDate
...


Purpose:

Stores a Vendor response to an AssessmentQuestion.


Responses are append-only.


Once submitted:

A Response is NEVER modified or overwritten.


If Vendor needs to change something:

Create another Response.


Example:

AssessmentQuestion

    Response v1
        Answer = No
        Submitted = Jan 5

    Response v2
        Answer = Yes
        Submitted = Jan 12


Both remain permanently.


========================================
16. CURRENT RESPONSE
========================================


For MVP:

The Response with the newest SubmittedDate is the
current Response.


Conceptually:

SELECT TOP 1 *
FROM Response
WHERE AssessmentQuestionId = X
ORDER BY SubmittedDate DESC


We currently do NOT use:

IsCurrent

or:

AssessmentQuestion.CurrentResponseId


Submitting a new Response requires a new Review.


An older Response's Review does NOT automatically
apply to the newer Response.

========================================
20. REVIEW
========================================


REVIEW
------
ReviewId (PK)

ResponseId (FK -> Response)

Status
Comments

ReviewedBy
ReviewedDate
...


Purpose:

Records analyst decision about one specific Response
and its supporting Evidence.


Statuses:

Not Reviewed
Flagged
Accepted
Rejected


----------------------------------------
NOT REVIEWED
----------------------------------------

Analyst has not reviewed current Response.

Non-terminal.


----------------------------------------
FLAGGED
----------------------------------------

Analyst cannot resolve current Response.

Vendor must provide corrected/additional information
or Evidence.

Non-terminal.


----------------------------------------
ACCEPTED
----------------------------------------

Analyst accepts current Response.

Terminal.


----------------------------------------
REJECTED
----------------------------------------

Analyst rejects current Response.

Terminal.

Rejected may represent an actual failed control.

It does NOT automatically prevent Assessment from
moving forward.


IMPORTANT:

Exact semantic distinction between Flagged and
Rejected still needs confirmation.


========================================
21. FLAGGED RESPONSE WORKFLOW
========================================


MVP does NOT include a back-and-forth chat system.


Example:

Response v1

    Answer = Yes

    Evidence =
    Old_PenTest_2021.pdf

    Review:

        Status = Flagged

        Comments =
        "Please provide a current penetration
         testing report."


Vendor does NOT edit Response v1.


Vendor submits:

Response v2

    Answer = Yes

    Evidence =
    PenTest_2026.pdf

    Review =
    Not Reviewed


Analyst reviews Response v2.


All history remains.


========================================
22. REVIEW COMPLETION
========================================


Assessment cannot proceed from Netrio Review to
Scoring until every included AssessmentQuestion's
current Response has a terminal Review status.


TERMINAL:

Accepted
Rejected


NON-TERMINAL:

Not Reviewed
Flagged


Example:

470 Accepted
20 Rejected
10 Flagged


Cannot proceed.


Later:

490 Accepted
10 Rejected
0 Flagged
0 Not Reviewed


Can proceed.


Excluded AssessmentQuestions are ignored.


If Vendor creates a new Response after previous
Response was Accepted:

New Response = Not Reviewed

Question therefore becomes unresolved again.

25. SCORING ARCHITECTURE
========================================


IMPORTANT:

SIG Domains and ScoringCategories are SEPARATE.


SIG DOMAIN:

Used for:

- Questionnaire organization
- Tier-based questionnaire scope


SCORING CATEGORY:

Used for:

- Calculating category scores
- Calculating overall risk score


A QuestionTemplate can therefore independently have:

DomainId

and:

ScoringCategoryId


For MVP:

One standard question maps to one ScoringCategory.


Custom questions do NOT participate in standard
scoring.

========================================
27. SCORING CONFIG VERSIONING
========================================


Scoring configurations are immutable after use.


If Netrio changes the scoring methodology:


Version 1

    ↓ copy

Version 2

    ↓ modify

Activate v2

Deactivate v1 for future use


Version 1 remains permanently.


Historical Assessments and scores are NOT
recalculated simply because a new configuration
becomes active.

========================================
31. CURRENT ASSESSMENT SCORE
========================================


Current score:

Newest AssessmentScore by CalculatedDate.


Conceptually:

SELECT TOP 1 *
FROM AssessmentScore
WHERE AssessmentId = X
ORDER BY CalculatedDate DESC


Therefore:

Assessment.OverallScore

does NOT exist.


AssessmentScore is the source of truth.

37. CURRENT DESIGN DECISIONS
========================================


1. Assessment is the central business object.

2. Vendor exists globally in our working design.

3. ClientVendor connects Client and Vendor.

4. ClientVendor contains business information.

5. Vendor Tier belongs to ClientVendor.

6. Tier is manually assigned.

7. Tier determines applicable SIG Domains.

8. Netrio Admin configures Tier-to-Domain mappings.

9. Tier changes affect future Assessments only.

10. Tier config changes affect future Assessments only.

11. Assessment snapshots its Tier.

12. Standard questionnaire is SIG.

13. SIG questions are organized into Domains.

14. Actual SIG structure will determine final
    Question-to-Domain cardinality.

15. Clients cannot create questions.

16. Netrio Admin controls question creation.

17. Custom questions may be requested outside the
    platform.

18. Netrio Admin creates custom questions.

19. Custom questions belong to one Client.

20. Custom questions may be reused by that Client.

21. Custom questions are unavailable to other
    Clients.

22. Custom questions have no SIG Domain.

23. Custom questions do not participate in standard
    scoring for MVP.

24. Tier rules generate the initial question scope.

25. Netrio Admin may add custom questions before
    Distribution.

26. Netrio Admin may exclude standard questions
    before Distribution.

27. Excluded questions remain for auditability.

28. Exclusion records who, when and why.

29. Assessment scope freezes upon Distribution.

30. Questions cannot change after Distribution.

31. AssessmentQuestion snapshots question data.

32. Responses are append-only.

33. Responses are never overwritten.

34. Newest SubmittedDate determines current Response.

35. New Response requires new Review.

36. Evidence attaches to Response.

37. Evidence may support multiple Responses.

38. Evidence has no independent review workflow.

39. Analyst reviews Response + Evidence together.

40. Review belongs to a particular Response.

41. Review statuses:

    Not Reviewed
    Flagged
    Accepted
    Rejected

42. Accepted and Rejected are terminal.

43. Not Reviewed and Flagged are non-terminal.

44. A Flagged Response cannot be edited.

45. Vendor submits a new Response after Flagging.

46. Clarification is handled with Review.Comments.

47. No chat/conversation system for MVP.

48. Assessment cannot reach Scoring while current
    Responses remain unresolved.

49. Rejected Responses do not inherently block
    Scoring.

50. Excluded questions do not require Responses.

51. Multiple questions may contribute to one Finding.

52. Findings and AssessmentQuestions are many-to-many.

53. SIG Domains and ScoringCategories are different
    concepts.

54. Domain controls questionnaire organization/scope.

55. ScoringCategory controls scoring.

56. One standard QuestionTemplate maps to one
    ScoringCategory for MVP.

57. One global ScoringConfig applies to every Client.

58. Client-specific scoring overrides are not
    supported for MVP.

59. ScoringConfig is versioned.

60. Used ScoringConfig versions are immutable.

61. Methodology changes create new ScoringConfig
    versions.

62. ScoringCategory belongs to ScoringConfig.

63. RatingThreshold belongs to ScoringConfig.

64. Assessment scoring history is append-only.

65. Each scoring run creates AssessmentScore.

66. Each AssessmentScore has CategoryScore records.

67. Assessment does not directly store OverallScore.

68. Newest AssessmentScore represents current score.

69. Historical weights are snapshotted.

70. Historical Risk Rating is snapshotted.

71. Activating a new scoring configuration does not
    rewrite historical scores.

72. Detailed scoring formula remains TBD.

73. Historical assessment information is preserved
    instead of overwritten wherever practical.
