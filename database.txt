WORKING MVP DESIGN:

A Vendor exists once globally.

Microsoft exists as one Vendor record even when
multiple Clients use Microsoft.

IMPORTANT:

The roadmap originally models each Vendor as
belonging to one Client.

Our working design instead uses:

Global Vendor

This remains an open requirement that should be
confirmed with the product owner.

PURPOSE:

The central business object.

Represents:

"Client X is assessing Vendor Y."


PERMISSION RULE:

Netrio Admin:
May initiate.

Netrio Analyst:
May initiate.

Client Admin:
May request an Assessment but cannot directly
initiate one.

Client Viewer:
Cannot initiate.

NOTE:

The exact persistence mechanism for a Client Admin's
Assessment request has not been modeled yet.


Client and Vendor are reached through:

Assessment
    -> ClientVendor
        -> Client
        -> Vendor


TierIdSnapshot preserves the Tier used when the
Assessment was created.


ScoringConfigIdSnapshot preserves the applicable
scoring configuration.


Assessment does not directly store OverallScore.

Score history is stored in AssessmentScore.

========================================
ASSESSMENT QUESTION GENERATION
========================================

ClientVendor

    ↓

Tier

    ↓

TierDomain

    ↓

SIG Domain

    ↓

QuestionTemplate

    ↓

AssessmentQuestion snapshot


PROCESS:

1. Assessment is initiated.

2. Read Tier from ClientVendor.

3. Store Tier as Assessment.TierIdSnapshot.

4. Retrieve applicable SIG Domains.

5. Retrieve applicable standard SIG questions.

6. Create AssessmentQuestion snapshots.

7. Apply permitted manual adjustments.

8. Freeze question scope at Distribution.

========================================
MANUAL QUESTION ADJUSTMENTS
========================================

Before Distribution, authorized Netrio personnel may:

- Add Client-specific questions
- Exclude standard questions
- Reverse exclusions


Client Admin may upload a Client questionnaire.

Client Admin does not directly modify individual
AssessmentQuestions for the MVP.


========================================
QUESTION EXCLUSION
========================================

Questions are not physically deleted from an
Assessment.

They are marked as excluded.


AssessmentQuestion:

IsExcluded = true
ExcludedBy = User
ExcludedDate = timestamp
ExclusionReason = reason


EXCLUDED QUESTIONS:

- Are not shown to Vendor
- Cannot receive Responses
- Do not require Review
- Do not participate in scoring


========================================
ASSESSMENT SCOPE FREEZE
========================================

BEFORE DISTRIBUTION:

Authorized Netrio personnel may:

- Add Client-specific questions
- Exclude questions
- Reverse exclusions


AFTER DISTRIBUTION:

Questions cannot be:

- Added
- Removed
- Excluded
- Restored
- Reworded
- Reweighted


The question scope becomes immutable when the
Assessment is distributed.


PERMISSION RULE:

Questionnaires may be sent by:

- Netrio Admin
- Netrio Analyst
- Client Admin


Assessment.DistributedBy and DistributedDate record
the distribution event.


========================================
RESPONSE
========================================

RESPONSE
--------
ResponseId (PK)
AssessmentQuestionId (FK -> AssessmentQuestion)
Answer
SubmittedBy (FK -> ApplicationUser)
SubmittedDate
...


PURPOSE:

Stores a Vendor response to an AssessmentQuestion.


AUTHORIZED CREATOR:

Vendor Contact.


RESPONSES ARE APPEND-ONLY.


A submitted Response is never modified.

A changed answer creates a new Response.


========================================
CURRENT RESPONSE
========================================

The Response with the newest SubmittedDate is the
current Response.


Conceptually:

SELECT TOP 1 *
FROM Response
WHERE AssessmentQuestionId = X
ORDER BY SubmittedDate DESC


A new Response requires a new Review.

An old Review does not apply to the new Response.

REVIEW

AUTHORIZED REVIEWERS:

NOT AUTHORIZED:

Client Admin
Client Viewer

STATUSES:

Not Reviewed
Flagged
Accepted
Rejected


NOT REVIEWED:

Non-terminal.


FLAGGED:

Additional or corrected information/evidence is
required.

Non-terminal.


ACCEPTED:

Terminal.


REJECTED:

Terminal.

May represent a failed control and does not
automatically block Assessment progression.


IMPORTANT:

The exact business distinction between Flagged and
Rejected still requires confirmation.


========================================
FLAGGED RESPONSE WORKFLOW
========================================

The MVP has no back-and-forth chat system.


Response v1:

Review = Flagged

Comments =
"Please provide a current penetration-test report."


Vendor does not edit Response v1.

Vendor submits Response v2.

Response v2 requires a new Review.

All historical Responses and Reviews are preserved.


========================================
REVIEW COMPLETION
========================================

An Assessment cannot proceed to Scoring until every
included AssessmentQuestion's current Response has
a terminal Review status.


TERMINAL:

Accepted
Rejected


NON-TERMINAL:

Not Reviewed
Flagged


Excluded AssessmentQuestions are ignored.


A new Response makes the AssessmentQuestion
unresolved until the new Response is reviewed.


========================================
SCORING ARCHITECTURE
========================================

SIG Domain and ScoringCategory are separate.


SIG DOMAIN:

Controls questionnaire organization and Tier-based
scope.


SCORING CATEGORY:

Controls scoring.


For MVP:

One standard QuestionTemplate maps to one
ScoringCategory.


Client-specific questions do not participate in
standard scoring.
